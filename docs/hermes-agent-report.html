Personal Agent Operations Report

Hermes Agent 개인 프로젝트 관리 구성안

프로젝트별 티켓 생성, 수정, 보관, 히스토리 기록, 진척도 추적, 이력서용 성과 정리를 하나의 로컬 운영 체계로 관리하기 위한 설계 보고서입니다.

작성일: 2026-07-05 대상 환경: 개인 Mac / 로컬 파일 기반 운영 권장 방식: Markdown + Git + 선택적 외부 도구 연동
핵심 목적 개인 프로젝트의 작업, 결정, 성과를 누락 없이 기록합니다.
운영 원칙 삭제보다 보관, 임의 변경보다 히스토리 우선입니다.
최종 산출물 프로젝트 로그, 티켓, 주간 리뷰, 이력서 성과 후보입니다.

1. 권장 방향

Hermes Agent는 Jira나 Notion을 그대로 복제하는 도구가 아니라, 개인 프로젝트 운영 비서로 구성하는 것이 좋습니다. 핵심 원장은 로컬 파일 시스템에 두고, Git을 통해 변경 이력을 남기며, 필요할 때만 GitHub Issues, Linear, Notion 같은 외부 서비스와 동기화합니다.

권장 결론: ~/Hermes를 개인 프로젝트 운영 저장소로 만들고, Hermes가 이 안에 티켓, 로그, 의사결정, 성과 기록을 append-first 방식으로 관리하게 합니다.

2. 로컬 디렉터리 구조

프로젝트별 기록을 독립적으로 보관하되, 공통 템플릿과 운영 규칙은 상위 디렉터리에 둡니다. 

~/Hermes/
  projects.yaml              # 프로젝트 목록, 목표, 상태
  inbox.md                   # 빠른 메모, 아이디어, 할 일 임시 수집
  agent-rules.md             # Hermes 행동 규칙
  templates/
    ticket.md
    weekly-review.md
    resume-bullet.md
  projects/
    my-project/
      project.md             # 목적, 범위, 성공 기준
      tickets/
        MYPROJ-001.md
        MYPROJ-002.md
      logs/
        2026-07.md           # 월별 작업 로그
      decisions.md           # 주요 의사결정과 이유
      metrics.md             # 수치 성과와 지표
      resume.md              # 이력서용 성과 후보

4. Hermes 내부 역할

하나의 에이전트가 모든 일을 하더라도, 프롬프트와 규칙 안에서는 역할을 나누는 편이 관리 품질이 좋습니다.

Planner

  • 아이디어를 티켓으로 변환합니다.
  • 기존 티켓과 중복 여부를 확인합니다.
  • 프로젝트 목표와 맞지 않는 작업은 backlog로 보냅니다.

Tracker

  • 티켓 상태 변경을 기록합니다.
  • 작업 로그와 커밋, PR, 문서 링크를 연결합니다.
  • 진행 중, 차단, 완료 항목을 요약합니다.

Historian

  • 매일 또는 매주 변경 이력을 요약합니다.
  • 주요 의사결정과 근거를 decisions.md에 남깁니다.
  • 실패한 시도와 배운 점도 기록합니다.

Resume Curator

  • 완료 티켓에서 이력서용 성과 후보를 추출합니다.
  • 성과를 문제, 행동, 결과 중심 문장으로 바꿉니다.
  • 수치가 없는 성과에는 측정 가능한 지표를 제안합니다.

5. 운영 규칙

Hermes의 행동 규칙은 ~/Hermes/agent-rules.md에 명시합니다. 규칙은 짧고 강하게 쓰는 편이 좋습니다. 

# Hermes Agent Rules

- 모든 프로젝트 작업은 반드시 프로젝트 디렉터리 아래에 기록한다.
- 새 작업 요청이 들어오면 먼저 기존 티켓과 중복 여부를 확인한다.
- 티켓 생성 시 성공 기준과 완료 조건을 반드시 포함한다.
- 티켓 수정 시 변경 전, 변경 후, 변경 이유를 로그에 남긴다.
- 티켓 삭제는 기본적으로 금지하고 archived 처리한다.
- 완료된 티켓은 resume.md에 성과 후보를 남긴다.
- 성과 기록은 가능한 경우 수치, 범위, 난이도, 사용자 영향을 포함한다.
- 매주 일요일에는 weekly review를 생성한다.

6. 자동화 루틴

주기 Hermes가 해야 할 일 산출물
매일 시작 진행 중, 차단된 티켓 요약. 오늘 처리할 티켓 3개 추천. daily note, 오늘의 우선순위
작업 중 티켓 생성, 상태 변경, 작업 로그, 결정 기록. 티켓 파일, logs/YYYY-MM.md
매주 완료, 진행, 중단 항목 요약. 다음 주 우선순위 제안. weekly-review.md, backlog 정리
매월 프로젝트별 성과와 측정 가능한 지표 정리. metrics.md, resume.md

7. 진척도 추적 방식

단순 완료율만 보면 프로젝트의 실제 상태를 놓치기 쉽습니다. Hermes는 완료율, 최근 작업 여부, 차단 항목, 핵심 결과물 존재 여부를 함께 봐야 합니다. 

Project progress =
  완료된 milestone 비율
  + 완료 티켓 / 전체 티켓
  + active / blocked 티켓 수
  + 최근 7일 작업 로그 유무
  + 핵심 결과물 존재 여부
  + resume-worthy outcome 수

상태 요약 예시

my-project
- 목표: MVP 출시
- 상태: 진행 중
- 완료: 12 / 30 tickets
- Blocked: 2
- 최근 작업: 2026-07-04
- 이력서 후보 성과: 3개
- 다음 추천 작업: MYPROJ-014 API 에러 처리

8. 이력서 성과 기록

완료된 작업은 단순한 할 일 완료가 아니라, 나중에 설명 가능한 성과로 정리해야 합니다. Hermes는 완료 티켓마다 아래 형태의 성과 후보를 남기도록 구성합니다.

9. 권한과 안전장치

권한 수준 허용 범위 비고
기본 허용 ~/Hermes 읽기/쓰기, 프로젝트 repo 읽기, Git 로그 읽기 개인 운영 기록을 만드는 데 필요합니다.
승인 후 허용 프로젝트 문서 수정, GitHub Issue 생성, PR 코멘트 작성 외부 서비스나 실제 프로젝트 산출물에 영향을 줄 수 있습니다.
기본 금지 파일 삭제, credential 접근, .env 접근, 승인 없는 외부 전송 개인 정보와 프로젝트 보안을 위해 제한합니다.

10. 1차 구축 순서

  1. ~/Hermes 디렉터리를 만들고 Git 저장소로 초기화합니다.
  2. projects.yaml, inbox.md, agent-rules.md를 만듭니다.
  3. 프로젝트별 project.md, tickets, logs, resume.md를 만듭니다.
  4. 티켓 템플릿과 주간 리뷰 템플릿을 고정합니다.
  5. Hermes에게 티켓 생성, 상태 변경, 로그 추가, 주간 리뷰 생성 명령만 먼저 맡깁니다.
  6. 운영이 안정되면 GitHub Issues, Notion, Linear 같은 외부 도구 연동을 추가합니다.
처음부터 자동화를 크게 만들기보다, 티켓과 로그가 꾸준히 쌓이는 구조를 먼저 완성하는 것이 중요합니다.
