Hermes Agent Blueprint

Daily Life Memory Assistant Architecture

Hermes Agent를 개인 회사의 운영팀처럼 구성하기 위한 프로필, SaaS 통합, 장기 기억 인프라 아키텍처 제안서입니다. 목표는 일정 관리가 아니라, 프로젝트와 인생 사건의 원본 기록, 맥락, 결정 근거, 증거, 회상 가능성을 장기간 보존하는 것입니다.

작성일: 2026-07-06 대상: 개인 Mac 중심 운영 + SaaS 연동 핵심 원칙: Hermes Ledger가 원장, SaaS는 전문 뷰
설계 원칙 Agent Profiles SaaS Integrations Infrastructure Data Model MVP Roadmap
Primary Memory 모든 사건은 Hermes Event Ledger에 먼저 append-only로 기록합니다.
Execution Surface Linear는 프로젝트, 티켓, 일정, 진행 히스토리의 작업 화면입니다.
Knowledge Surface Notion은 문서, 결정, 사건, 관계, 증거를 읽기 좋은 inventory로 관리합니다.
Recall Layer 키워드 검색, 의미 검색, 타임라인 재구성으로 과거 맥락을 복원합니다.

1. 설계 판단

Hermes Agent는 Notion이나 Linear의 자동화 봇이 아니라, 당신의 장기 기억을 관리하는 상위 운영 계층이어야 합니다. Linear는 실행 상태를 잘 다루고, Notion은 문서와 지식 inventory를 잘 다루지만, 둘 중 하나만 원장으로 삼으면 서비스 변경, 권한 문제, 데이터 누락, 검색 한계에 묶입니다.

권장 결론: Hermes 자체에 append-only event ledger를 두고, Linear와 Notion은 각각 프로젝트 실행 뷰와 문서 지식 뷰로 동기화합니다. 원본 파일, 이메일, 스크린샷, 계약서, PDF, 커밋, 티켓 변화는 Hermes가 별도 인덱싱해야 합니다.

기억 시스템의 핵심 원칙

원칙 의미 구현 방식
Capture first 정리보다 수집이 먼저입니다. 입력이 귀찮으면 시스템은 죽습니다. CLI, 모바일 share sheet, 브라우저 클리퍼, 이메일 라벨, 파일 dropbox를 둡니다.
Raw before summary LLM 요약은 파생물입니다. 원본이 사라지면 증거 가치와 재검증 가능성이 사라집니다. 원본 파일, URL, 이메일 헤더, 스크린샷, 커밋 해시를 변경 불가능한 위치에 보존합니다.
Timeline as backbone 인생 히스토리는 결국 시간순 사건 복원 문제입니다. 모든 event에 timestamp, source, actor, related entities, evidence 링크를 강제합니다.
Approval boundary 기록 agent가 임의로 외부 전송, 삭제, 법적 판단, 금전 결정을 하면 안 됩니다. 읽기, 쓰기, 외부 발행, 삭제, 민감 문서 접근을 권한 레벨별로 분리합니다.

2. Hermes Agent Profiles

프로필은 완전 독립 자율 에이전트라기보다, 동일한 Hermes Core 위에서 다른 프롬프트, 도구 권한, 산출물 책임을 가진 역할 단위로 보는 편이 안전합니다. 각 프로필은 자신의 업무를 기록하되, 모든 결과를 Event Ledger에 남겨야 합니다.

Chief of Staff

하루 운영의 지휘자입니다. 오늘 일정, 활성 프로젝트, 막힌 항목, 긴급한 응답, 다음 행동을 하나의 briefing으로 압축합니다.

  • daily briefing / evening shutdown 생성
  • 우선순위 충돌 탐지
  • 놓친 follow-up과 약속 추적
CalendarLinearNotion

Capture Router

모든 입력을 받아 적절한 저장소와 스키마로 라우팅합니다. 가장 중요한 프로필입니다. capture가 쉬워야 Hermes가 살아남습니다.

  • 빠른 메모, 링크, 파일, 스크린샷 ingest
  • event type, project, tag, sensitivity 자동 분류
  • 중복 문서와 기존 사건 연결
InboxClassifierDedupe

Project Manager

Linear 중심의 실행 관리자입니다. 프로젝트, milestone, ticket, deadline, 상태 변화, blocked reason을 매우 상세하게 관리합니다.

  • 프로젝트별 티켓 생성 및 상태 전이
  • ticket history와 관련 event 연결
  • 주간 프로젝트 리뷰와 next action 추천

Linear Sync Manager

Hermes와 Linear 사이의 데이터 일관성을 책임지는 adapter 역할입니다. Project Manager와 분리해야 동기화 오류를 통제하기 쉽습니다.

  • issues, projects, cycles, comments, labels 동기화
  • webhook event를 Hermes event로 정규화
  • Linear ID와 Hermes ID 매핑 유지
GraphQLWebhooksID map

Archivist

Notion 중심의 문서 librarian입니다. 살면서 마주한 문서, 링크, PDF, 논문, 계약서, 회의 메모를 읽기 좋은 inventory로 정리합니다.

  • 문서 database 생성 및 속성 관리
  • 원본 파일과 Notion page 연결
  • 문서별 요약, 중요도, 재방문 이유 기록

Historian

사건을 시간순으로 복원하는 프로필입니다. 프로젝트 변경, 법적 분쟁 가능 사건, 커리어 결정, 구매 결정의 흐름을 timeline으로 만듭니다.

  • 날짜별 사건 요약
  • 관련자, 조직, 문서, 티켓 연결
  • "그때 무슨 일이 있었나" 질문에 답할 timeline 구성

  • 선택지, 판단 기준, trade-off 기록
  • 결정 당시 근거와 나중의 결과 분리

  • 증상, 원인 가설, 시도, 결과 기록

  • 원본 파일, 대화, 이메일, 계약서, 입금 기록 보존

  • 논문/문서 metadata 추출

  • 성과 후보 문장 생성

3. Integrate 해야 할 SaaS와 기능

SaaS는 Hermes의 대체제가 아니라, Hermes가 연결하는 전문 inventory입니다. 핵심은 "어디에 저장할 것인가"보다 "Hermes가 어떤 사건 ID로 모든 흔적을 연결할 것인가"입니다.

Tier SaaS / Tool Hermes에서 맡길 기능 주요 데이터 주의점
Core Linear 프로젝트, 티켓, cycle, milestone, status, priority, comment, blocked reason, due date 관리 Issue, Project, Cycle, Comment, Label, Team, Workflow State Hermes Event ID를 Linear issue/comment에 backlink로 남겨야 합니다.
Core Notion 문서 inventory, 사건 archive, decision record, incident note, person/org database, evidence index Page, Database, Comment, File, View, Relation, Property Notion page는 보기 좋은 뷰입니다. 원본 파일과 ledger는 별도로 보존합니다.
Core Google Calendar / Apple Calendar 일정, deadline, meeting, 반복 리뷰, follow-up reminder, 실제 시간 사용 기록 Event, Attendee, Location, Reminder, Recurrence calendar event와 Hermes event를 연결해 "그날 무슨 일이 있었는지" 복원합니다.
Core Google Drive / iCloud Drive / Dropbox PDF, 계약서, 스크린샷, exported chat, receipt, raw evidence의 파일 저장소 File, Folder, Metadata, Share Link, File Revision 민감 문서는 암호화 vault 또는 접근 제한 폴더로 분리합니다.
Important Gmail / Email 중요 메일, 계약/분쟁/영수증/서비스 운영 메일 capture, thread timeline 구성 Message, Thread, Label, Header, Attachment 전체 inbox ingest보다 라벨 기반 선택 ingest가 안전합니다.
Important GitHub / GitLab 커밋, PR, issue, release, code review, incident fix evidence 연결 Commit, Pull Request, Issue, Release, Review, Check Run Linear ticket, Hermes event, commit hash를 삼각 연결합니다.
Important 1Password / Apple Passwords API token과 secret의 보관 위치. Hermes는 값을 읽지 않고 참조명만 사용합니다. Secret Reference, Vault Name, Rotation Date Hermes가 raw secret을 저장하지 않도록 강제합니다.
Important Sentry / Grafana / Datadog / PostHog 장애, 에러, 성능 문제, 사용자 행동 지표를 troubleshooting record에 연결 Error Event, Trace, Metric, Alert, Dashboard Link 운영 지표는 resume/career evidence로도 재사용됩니다.
Optional Slack / Discord / Telegram 중요 대화, 합의, 운영 논의, 분쟁 가능 thread의 선택 capture Message, Thread, Channel, Attachment, Reaction 개인정보와 상대방 동의 이슈가 있으므로 수집 범위를 좁힙니다.
Optional Readwise Reader / Raindrop / Browser Bookmarks 읽은 문서, 하이라이트, 나중에 다시 볼 링크, 기술 조사 흔적 관리 Article, Highlight, Tag, URL, Read State Research Librarian의 자료 입력원으로 사용합니다.

5. Core Data Model

Hermes의 최소 원자 단위는 ticket이 아니라 Event입니다. 프로젝트 티켓, 문서, 결정, 법적 이슈, 장애, 구매 결정, 커리어 고민은 모두 event로 기록하고, 필요할 때 특화 record를 붙입니다. 

Event
  id: HME-2026-000001
  timestamp: 2026-07-06T10:30:00+09:00
  type: project | document | decision | incident | legal | career | purchase | research
  sensitivity: public | personal | confidential | legal_sensitive
  title:
  summary:
  raw_sources:
    - kind: file | url | email | ticket | commit | calendar_event
      source_id:
      immutable_ref:
      sha256:
  actors:
    people: []
    organizations: []
  relations:
    projects: []
    tickets: []
    documents: []
    decisions: []
  next_actions: []
  confidence: human_confirmed | agent_inferred | imported
  created_by_profile:
  external_refs:
    linear:
    notion:
    github:
    calendar:

Project Record

Linear와 연결되는 실행 단위입니다. 목표, 범위, milestone, ticket set, status, deadline, stakeholder, 성공 기준, 완료 증거를 보관합니다.

Document Record

Notion과 연결되는 지식 단위입니다. 원본 파일 위치, 요약, 태그, 관련 decision, 관련 프로젝트, 재방문 이유, 인용 가능성을 보관합니다.

Decision Record

선택지, 판단 기준, 결정 근거, 리스크, 반대 의견, 재검토 조건, 실제 결과를 분리해서 저장합니다.

Evidence Record

법적/계약/분쟁 가능성이 있는 자료를 원본 중심으로 저장합니다. 요약보다 hash, timestamp, source, chain of custody가 중요합니다.

법적 이슈 주의: Hermes는 법률 조언자가 아니라 기록 정리자여야 합니다. 사실 타임라인, 원본 증거, 관련자, 금액, 날짜, 커뮤니케이션 기록을 정리하되 법적 판단은 변호사 검토 대상으로 분리합니다.

6. 예상 명령 인터페이스

Hermes는 복잡한 UI보다 빠른 capture와 recall 명령이 먼저 필요합니다. 아래 명령들이 가능해지면 daily life 관리 비서로서 실제 효용이 생깁니다. 

hermes capture "오늘 A사 대표와 정산 이슈를 30분 통화함. 다음 주 월요일까지 자료 보내기로 함."
hermes doc add ./contract.pdf --type contract --sensitivity legal_sensitive
hermes ticket create --project "Ultimate Hermes" --title "Linear sync adapter 구현"
hermes incident "prod API timeout" --project "my-service"
hermes decision "Notion을 문서 inventory로 쓰고 Hermes ledger를 원장으로 둔다"
hermes remember "작년에 Vercel 배포 에러 해결했던 기록 찾아줘"
hermes timeline "A사 정산 관련 이슈"
hermes evidence "법적 분쟁 가능성이 있는 A사 관련 자료 패킷 생성"
hermes status --all-projects
hermes review weekly

7. MVP 구축 순서

  1. Local Hermes Ledger: SQLite 또는 Postgres로 Event, Entity, Source, ExternalRef 테이블을 먼저 만듭니다.
  2. Capture CLI: 텍스트, URL, 파일, 스크린샷을 빠르게 넣는 명령부터 만듭니다.
  3. Notion Inventory: Documents, Decisions, Incidents, Evidence, People/Orgs database를 생성하고 Hermes ID를 relation key로 둡니다.
  4. Linear Sync: 프로젝트와 티켓을 동기화하고, Linear webhook을 Hermes event로 저장합니다.
  5. Search Layer: SQLite FTS로 시작하고, 문서가 많아지면 embedding index를 붙입니다.
  6. Daily Briefing: Chief of Staff가 Calendar, Linear, Notion, Hermes Ledger를 읽어 매일 아침 요약을 만듭니다.
  7. Evidence Mode: legal_sensitive 자료는 hash, 원본 경로, 타임라인, export bundle을 별도 흐름으로 처리합니다.
초기 범위 제한: 처음부터 모든 SaaS를 붙이면 실패 확률이 높습니다. 1차는 Hermes Ledger + Capture CLI + Notion Documents + Linear Projects만 구현하고, Calendar와 GitHub를 2차로 붙이는 편이 좋습니다.

8. 공식 문서 참고

아래 문서는 통합 가능성을 확인하기 위해 참고한 공식 문서입니다. 구현 시에는 각 서비스의 OAuth scope, rate limit, webhook 검증, 데이터 보존 정책을 별도로 점검해야 합니다.

  • Linear GraphQL API: issues, teams, workflow states, mutations, webhooks, OAuth/API key.
  • Notion API Overview: pages, databases, comments, file uploads, search, webhooks, connection permissions.
  • Google Calendar API: calendars, events, recurring events, reminders, synchronization, push notifications.
  • Gmail API: messages, threads, labels, search/filter, synchronization, push notifications.
  • Google Drive API: file upload/download, search, sharing, app-specific storage, file activity.
  • GitHub REST API: repositories, issues, pull requests, commits, releases, webhooks, automation.
